# 2026-10-17 — Observed injection: a cmux rung for dictated prompts and device answers (#541)

#541 reported that voice prompts never reached Claude Code sessions running in
[cmux](https://cmux.com): `delivered=false (no reachable terminal for ttysNNN)`.
The ladder knew only tmux, iTerm2 and Terminal.app. On the way to that line, the
Terminal.app rung also ran `tell application "Terminal"` for a tty Terminal.app
does not own, and macOS asked the user to let `node` control Terminal.app.

**Change:** a cmux rung between tmux and iTerm2, for both `injectObservedText`
and `injectObservedSelection`. The daemon reads `CMUX_SURFACE_ID` (and
`CMUX_SOCKET_PATH`) from the agent process's own environment with
`ps -E -ww -o command= -p <pid>`. The observed session already carries that pid,
so neither the hook command nor its three mirrored installers change. Once the
host is known to be cmux, the ladder does not fall through to AppleScript.

**Measured on cmux 0.65.1, macOS 27.0.1:**

- `cmux send --surface <uuid>` resolves the workspace by itself. The
  `CMUX_WORKSPACE_ID` in the environment is only where the surface was at launch,
  so it is not passed.
- Plain `send` turns a literal `\n` in the text into Enter, which would submit a
  dictated line early. `send --paste` keeps it as text. Japanese text arrives intact.
- While the prompt holds typed text, `send` fails with `holds text someone is typing`.
  While a question or dialog is open, both `send` and `send-key` fail with
  `waiting on a question or dialog`. `send-key Enter` after our own paste is not
  refused. So text goes paste → 250 ms → Enter and never uses `--force`. A device
  answer uses `send-key --force`, because answering that dialog is its purpose.
  Claude Code's folder-trust screen comes before hooks run, and cmux does not see
  it as a dialog.
- Under "cmux processes only", `send` from a LaunchAgent daemon gets only
  `Broken pipe (errno 32)`. `ping` gets `Access denied - only processes started
  inside cmux can connect`, so `ping` runs on that branch only, and the delivery
  reason quotes it.

**Verified end to end** with the LaunchAgent daemon, a D200X and this repository's
session in cmux:

- Automation mode: `voice: "…" -> observed:claude:… delivered=true via cmux`.
- "cmux processes only": `delivered=false (cmux socket refused (ERROR: Access denied
  - only processes started inside cmux can connect); set Socket Control Mode to
  Automation mode in cmux Settings)`.
- A device answer to an AskUserQuestion: `observed selection injected via cmux
  (idx 1, …)`. The second option was the one recorded.

**Unverified:** a tagged or debug cmux build on its own socket, which is the case
`CMUX_SOCKET_PATH` is passed on for. A session in tmux inside cmux is matched by
the tmux rung first, by tty, and was not run. Gates:
`bridge/src/__tests__/observed-inject.test.ts` (`parseCmuxEnv`, refusal reading,
and the ladder against a fake `execFile`).
